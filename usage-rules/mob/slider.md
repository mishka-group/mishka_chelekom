# slider (mob)

A draggable value along a range, on Mob's native `Slider`. See [README](README.md) for the rules
every Mob component shares.

## Generate
`mix mishka.ui.gen.mob slider` → `lib/<app>/components/slider.ex`, tag `<Slider />`. With
`--module-prefix mishka_` it is `<MishkaSlider />`.

## Example

```elixir
~MOB"""
<MishkaSlider value={@volume} min={0} max={100} step={5} label="Volume" show_value={true}
              on_change={:volume} />
"""

# Controlled: the screen owns the value.
def handle_info({:change, :volume, v}, socket) do
  {:noreply, Mob.Socket.assign(socket, :volume, v)}
end
```

## Props

| Prop | Values | Default |
|---|---|---|
| `value` | number | `min` |
| `min` / `max` | number | `0` / `100` |
| `step` | number | `nil` — continuous |
| `values` | `[lo, hi]` | `nil` — two thumbs, overrides `value` |
| `orientation` | `:horizontal` · `:vertical` | `:horizontal` |
| `length` | number | `160` — track length when vertical |
| `label` | string | `nil` |
| `show_value` / `value_text` | boolean / string | `false` / `nil` |
| `color` | colour token / ARGB int | platform |
| `on_change` | event tag (atom) | — |

Helpers: `steps/3`, `snap/2`, `resolve/3`, `parse_range/1`.

## Five things to know

**`step` is snapped by the widget, not by you.** It becomes Compose's `steps`, so the control snaps
itself. Do **not** snap in the handler and assign the result back — that is what made the stepped
slider jump: the screen snapped, wrote it back, and the bridge yanked the thumb to the snap point
while the finger was still down. `snap/2` remains for clamping to rules the widget cannot express
(the widget only snaps to an even division of the range).

**A range reports one string, not two numbers.** The change channel carries a single value, so two
thumbs come back as `"lo,hi"`. Decode with `parse_range/1`:

```elixir
def handle_change(:price, reported, socket) do
  case MishkaSlider.parse_range(reported) do
    {lo, hi} ->
      moved = if lo != hd(socket.assigns.price), do: :lo, else: :hi
      {lo, hi} = MishkaSlider.resolve({lo, hi}, moved, min_gap: 5, collision: :push,
                                      min: 0, max: 100)
      Mob.Socket.assign(socket, :price, [lo, hi])

    :error ->
      socket
  end
end
```

**The gap and the collision rule are yours, and they are pure.** `resolve/3` takes the dragged pair,
which thumb the finger has, and `min_gap` / `collision` — `:push` carries the other thumb along,
`:stop` holds the dragged one at the boundary. It is arithmetic, so it behaves identically on every
platform and is worth unit-testing rather than dragging.

**Vertical needs a `length`.** A rotated slider cannot inherit a width, so it is drawn inside a box
as tall as the track is long. Give it one or it defaults to 160.

**It is controlled — but the screen only gets to move the thumb on release.** While a drag is in
flight the thumb follows the finger alone. Accepting the screen's value mid-drag is what made the
slider stutter: every move sends a value, the screen re-renders the whole tree and sends it back,
and by the time that lands the finger has moved on — so the "current" value in it is stale and
drags the thumb backwards. On release the next render is accepted, which is when a clamp, a snap or
a rejection takes effect. Design your handler for that: correct the value freely, just do not expect
the correction to appear until the finger lifts.

iOS's `MobSlider` seeds its state once and never resyncs at all, so there a clamp never lands. Same
shape as the Switch.

## Range and vertical are Android-only

SwiftUI ships neither a range slider nor a vertical one, so both were built in the Android bridge,
which lives in this repo. The iOS renderer is in the `mob` dependency and cannot be changed from
here — on iOS a `values` slider falls back to a single thumb and `orientation` is ignored.

The Elixir half is portable and already shared: `resolve/3`, `parse_range/1` and `steps/3` run the
same everywhere. See `development/mob/IOS_TODO.md` for exactly what the iOS side needs.

Note also that bridge fixes made here do not reach apps generated by `mix mishka.ui.gen.mob` — those
get the mob templates, not this repo's `MobBridge.kt`.
